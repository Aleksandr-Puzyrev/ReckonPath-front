# Что требуется для завершения интеграции Reckon Path

Статус сверки на 26.11.2026. Сервер `283c87e`. Клиент использует 124 из 125 операций Swagger. Альтернативный `POST /continue` не нужен отдельному экрану, кампания уже использует `POST /campaign/games/{id}/continue`. [Аудит маршрутов](client-integration-audit.md)

Клиентская регистрация FCM на обеих платформах реализована. Для iOS проверены сценарии токена на моках и генерация нативного проекта с тестовым plist. Для живой доставки нужны настройки ниже.

## Конфигурация и доступы

| Задача | Что предоставить или настроить | Что проверим |
| --- | --- | --- |
| FCM на iOS | Подтвердить итоговый iOS bundle ID. Для него добавить приложение в тот же Firebase-проект, который использует сервер. Передать путь к `GoogleService-Info.plist` через `RECKON_IOS_GOOGLE_SERVICES_FILE`. Загрузить APNs-ключ в Firebase, включить Push Notifications для App ID и подготовить подписанную Debug-сборку для физического iPhone. | Запрос разрешения, регистрацию FCM-токена, доставку тестового пуша, смену токена, отключение уведомлений и выход из аккаунта. |
| FCM на Android | Передать путь к `google-services.json` соответствующего Android-пакета через `RECKON_ANDROID_GOOGLE_SERVICES_FILE`. Настроить на бэкенде отправщик FCM для того же проекта. | Доставку тестового пуша и очистку токена. |
| VK ID | Публичный `EXPO_PUBLIC_VKID_CLIENT_ID`, зарегистрированный redirect URI `reckonpath://oauth/vk` или согласованный эквивалент. Включить провайдера на сервере. | Вход, привязку и отвязку. |
| Яндекс ID | Публичный `EXPO_PUBLIC_YANDEX_CLIENT_ID`, зарегистрированный redirect URI `reckonpath://oauth/yandex` или согласованный эквивалент. Включить провайдера на сервере. | Вход, привязку и отвязку. |

OAuth-секреты, ключ Firebase service account и ключ APNs хранятся в серверной конфигурации или консоли провайдера. Клиентские файлы Firebase исключены из Git.

## Тестовые данные

- Тестовый аккаунт с ненулевым балансом, доступом к офлайн-кампании и дейли. Для проверки офлайна нужен актуальный пакет уровней. Проверка включает завершение уровня без сети и синхронизацию после восстановления связи.
- Опубликованный предмет с Lottie и доступной ценой. Желательно задать разные цвета слоёв для светлой и тёмной тем. Проверка включает витрину, покупку, экипировку и воспроизведение в одиночной партии.
- Код активного события, доступная карта и тестовый сценарий получения приза. Проверка включает превью, вступление, игру и получение награды. Полезен также код завершённого события.
- Достижение, по которому тестовый аккаунт может забрать награду. Проверка включает получение награды и обновление её статуса.
- Два тестовых аккаунта для проверки уведомлений о друзьях. В текущей версии сервера автоматические типы уведомлений зарегистрированы для канала `friends`.

## Решения и работа на бэкенде

| Задача | Что нужно решить или сделать |
| --- | --- |
| Реклама за награду | Выбрать рекламную сеть и предоставить тестовые ID rewarded-блоков для iOS и Android. На сервере добавить `GET /ads/limits`, `POST /ads/intent`, `GET /ads/intent/{id}` и проверку подтверждений сети. Отдельно согласовать выдачу дополнительных ходов и восстановление серии за рекламу. |
| Значки профиля | Подтвердить, возвращаем ли выбор трёх значков. Если да, серверу нужны хранение выбора и выдача активных значков в профиле. Список достижений и получение наград уже подключены. |
| Трек наград события | Подтвердить, нужен ли трек с жетонами. Текущий API поддерживает таблицу и призы за места. Для трека нужны баланс жетонов, прогресс и получение наград по ступеням. |
| Выход со всех устройств | На сервере удалить push-токены отозванных устройств или исключать такие устройства при отправке. Клиент очищает токены текущего устройства при локальном выходе. |
| Остальные каналы уведомлений | Если требуется доставка по всем переключателям, зарегистрировать серверные типы и события для остальных каналов. |
| Lottie в PvP | Подтвердить отдельный объём, если эффекты понадобятся в PvP. Согласованное подключение покрывает онлайн- и офлайн-кампанию и дейли. |

Подробности по остальным расхождениям со спецификацией есть в [списке серверных задач](backend-todo.md) и [реестре расхождений](../backend-discrepancies.md).
