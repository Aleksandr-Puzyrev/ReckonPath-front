# Сверка мобильного клиента с бэкендом

26.11.2026. Рабочая копия клиента на базе `6314544`, бэкенд `283c87e`. В `docs/swagger.yaml` бэкенда 125 операций по уникальным парам HTTP-метод и путь. Все 121 пары в Debug из `BACKEND_ROUTES` присутствуют в Swagger. Ниже учтены остальные 4, включая 3 прямых подключения. Сверка показывает маршрутизацию и использование в исходниках. На iOS с локальным API проверены пустые списки событий и достижений и ошибка неизвестного кода. Вступление, игра и получение наград проверены на моках. Для проверки на сервере нужны тестовые данные.

| Операций | Маршруты | Статус |
| ---: | --- | --- |
| 3 | `GET /arena/ws`, `GET /document`, `GET /shop/images/{file}` | Сокет арены, политика конфиденциальности и изображения магазина идут напрямую. См. `src/shared/ws/ws.ts`, `src/shared/api/open-privacy-policy.ts`, `src/entities/item/model/shop-of.ts`. |
| 1 | `POST /continue` | Альтернативный вызов продолжения по `attempt_id` без `seq`. Клиент уже продолжает онлайн-партию через `POST /campaign/games/{id}/continue`. |

По решению [0067](../decisions/0067-events-and-achievements-api.md) подключены 8 операций событий и 2 операции достижений. Завершённые события открываются по коду. Карточка события не содержит статуса участия или получения приза, поэтому клиент показывает подтверждение после ответа соответствующей операции. Выбор трёх значков отложен.

По решению [0068](../decisions/0068-remaining-backend-integration.md) подключены статистика кампании и проверка ника, история уведомлений и обращений, результат дейли за дату и публичное превью события. Подключены вход, привязка и отвязка VK ID и Яндекс ID. Кнопки провайдера появляются при заданном публичном client ID. Для живой проверки у провайдера должен быть зарегистрирован redirect URI из `.env.example`, а в бэкенде включён соответствующий провайдер.

По решению [0069](../decisions/0069-offline-campaign.md) подключены загрузка зашифрованного набора и отправка завершённых офлайн-попыток. Загрузку и расшифровку уровня проверили с локальным API на iOS. Синхронизацию после восстановления сети проверили с моками.

По решению 0068 подключены чтение и сохранение настроек уведомлений устройства. Клиент отправляет язык и часовой пояс, а пользователь настраивает четыре канала сервера. На Android подключены системное разрешение, регистрация и удаление FCM-токена, обновление при ротации и тестовый маршрут только в Debug. Для сборки нужен `RECKON_ANDROID_GOOGLE_SERVICES_FILE` с клиентской конфигурацией Firebase, а для живой доставки бэкенду нужен настроенный отправщик FCM. Реестр `notify.Kinds` в этом коммите содержит только типы уведомлений канала `friends`.

Клиент удаляет токены текущего устройства с настроенным FCM перед локальным выходом. В `283c87e` серверный выход со всех устройств отзывает сессии без удаления токенов других устройств. Для прекращения доставки после удалённого отзыва бэкенд должен удалять токены или исключать устройства без действующей сессии. Для доставки на iOS выбран FCM по решению [0071](../decisions/0071-ios-push-provider.md). Клиент iOS запрашивает разрешение и регистрирует, обновляет и удаляет FCM-токен через те же серверные маршруты. Нативная конфигурация iOS проверена через Expo Prebuild с тестовым plist. Для проверки доставки нужен реальный plist, APNs в Firebase и подписанная сборка. [Требования и тестовые данные](integration-requirements.md)

Предпросмотр витрины загружает серверные композиции Lottie через `GET /shop/files/{file}`. Вариант темы определяет файл и цвета слоёв. Текстуры поля, аватара и рамки используют тот же маршрут. По решению [0070](../decisions/0070-equipped-solo-effects.md) эффекты тапа, открытия цели и победы берутся из экипировки и воспроизводятся в онлайн- и офлайн-кампании и дейли. Витрина показывает опубликованные эффекты с поддерживаемым Lottie-ассетом. Их можно экипировать из карточки предмета.

В обратную сторону в клиентском OpenAPI есть `POST /ads/intent`, `GET /ads/intent/{id}` и `GET /ads/limits`, которых нет в Swagger этого коммита. Эти операции отсутствуют в `BACKEND_ROUTES`.

Решения 0060–0071 описывают уже принятые интеграции. Реестр расхождений и открытых серверных задач находится в [`../backend-discrepancies.md`](../backend-discrepancies.md) и [`backend-todo.md`](backend-todo.md).
