# Ответы на вопросы бэкенда (FRONTEND.md, раздел 0)

Для разработчика бэкенда Reckon Path. Ответы на вопросы 1–10 из раздела «Что ждём от фронтенда». Написано по бэкенду `bb3f885`, сверено с `a709480`, 16.11.2026.

**Главное.** Клиент подстраивается под бэкенд, а не наоборот (решение `docs/decisions/0060`):
- кампания идёт серверными партиями: `play` → тап за тапом;
- арена работает по протоколу и правилам из FRONTEND.md §10;
- гостевого режима в приложении пока нет.

Что клиент обойти не может, собрано в `backend-todo.md`.

Пометка **«ждём решения продукта»** значит, что ответа пока нет. Он придёт отдельно.

## 1. Офлайн-кампания (K1–K10, K29, K30)

**Модель — ваша.** Клиент играет кампанию через `POST /campaign/levels/{n}/play` и `POST /campaign/games/{id}/tap`. Поле рисуется по `cells` из ответа, свой движок для кампании клиент не использует. Поэтому:
- `POST /attempts:batch` и `GET /progress` для кампании **не нужны**;
- векторы движка и паритет правил сейчас не нужны;
- переименовывать режимы (`number / hot_cold / course`) и поля клетки **не нужно**: клиент берёт ваши имена.

**Без сети** клиент пока кампанию не играет и показывает «Нужна сеть». Пакеты `/campaign/offline/*` не использует. Что понадобится, когда к ним вернёмся, — в `backend-todo.md`, раздел P2.

**Контент.** 100 уровней приложения нужно загрузить в админку. В репозитории клиента:

```
npm run content:export-backend
```

Команда создаёт `backend-levels.json`:
- `worlds[]` — 8 миров с названиями и подзаголовками RU/EN, `first_level`, `last_level`;
- `levels[]` — `number`, `world`, `title {ru, en}`, `tutorial`, `introduces[]` и `level` в формате `game.Level`. Мост — клетка `b`, режимы — ваши имена, у обучения `limit: 0`.

Ключи обучения: уровень 1 — `tut_first_level`, уровень 2 — `tut_moves_limit`. Другие клиенту не нужны.

## 2. Значки (S4)

По ТЗ это два разных вида значков, оба занимают один слот профиля «бейдж (до 3)» (Часть 1 §6.4):

- **Достижения** выдаются автоматически и не продаются.
- **Декоративные значки** продаются в витрине на вкладке «Профиль». Отсюда тип «БЕЙДЖ».

Значка, который можно и купить, и получить за условие, ТЗ не предусматривает.

Условия из ТЗ:

| Условие | Награда | Источник |
|---|---|---|
| Серия 7 дней, id `streak_7` | ◆ 15 за веху и значок один раз | Часть 1 §4.4, DLY-12 |
| Серия 30 дней | значок; ◆ 60 — это награда за веху серии | Часть 1 §4.4 |
| Все уровни мира на 3★ | ◆ 25 и значок | Часть 1 §3.6 |

Ещё пять условий есть только в макете: лига Gold, лига Platinum, уровень 25, «карта остановила 10 игроков», все уровни.

Окончательный список, правило для лиг и «один значок на мир или по значку на каждый» — **ждём решения продукта**. В приложении достижений пока нет, делать сейчас ничего не нужно.

## 3. Рекламная сеть

Какую сеть подключать первой, ключи и формат колбэков — **ждём решения продукта**.

До этого клиент не показывает «+3 хода за рекламу» в кампании: сейчас вы отвечаете на него `continue_method`. Пустой `ads_network` в `/bootstrap` клиент читает как «реклама выключена».

Поток с подтверждением просмотра на сервере (SSV) по ТЗ (Часть 7 §6):
1. `POST /ads/intent {placement, ref}` → `{adIntentId, customData, network, unitId, leftToday}`;
2. показ рекламы с `customData = adIntentId`;
3. колбэк сети `GET /ads/ssv/{network}`;
4. клиент опрашивает `GET /ads/intent/{id}` до 10 секунд.

## 5. Пеленг дня и серия

В `a709480` пеленг дня и серия появились на бэкенде. Клиент подключит их отдельной задачей и подстроится под ваш формат. До этого пеленг дня в приложении локальный и открывается по `unlocks.daily` из `GET /campaign`.

Ниже — как это устроено по ТЗ, для сверки.

**Уровень дня** генерируется детерминированно из сида `YYYY-MM-DD` (FNV + mulberry32):
- алгоритм — Часть 6;
- пошаговое описание — `packages/engine/docs/daily-generator.md`;
- проверка — векторы `daily` и `dailyTier`.

Детали генерации:
- EPOCH = `2026-10-01`;
- тир = `min(20, 1 + floor(daysSince(EPOCH) / 7))`;
- если уровень не построился, берётся запасной из 30 ручных;
- id — `d-YYYY-MM-DD`.

**Часовой пояс — UTC.** Игровые сутки начинаются в 00:00 UTC, чтобы лидерборд был общим (Часть 1). В `a709480` `day_key` уже по UTC.

**Форматы** (Часть 7 §4):
- `GET /daily/{date}` → `{date, override, leaderboardPreview: {top, median}, me: {played, result, rank}}`;
- `GET /daily/history?days=30` → `{days: [{date, result: "won" | "lost" | null, stars, restored}]}`, новые дни первыми (решение 0017);
- `GET /streak` → `{current, best, lastDay, restorable, restoreUntil, restoreMethods, price}`;
- `POST /streak/restore {method}` → `{streak, wallet}`, ошибка `streak_not_restorable`.

**Награды и правила** (Часть 1 §4):
- засчитанная попытка: ● 30, при победе ещё ● 10 за каждую звезду; XP +15;
- серия 3 / 7 / 14 / 30 дней: ◆ 5 / 15 / 30 / 60, на 7 и 30 днях ещё значки;
- топ-10 дневного лидерборда: ◆ 10;
- пропущен 1 день — серию можно восстановить в течение суток за рекламу или ◆ 30, не чаще раза в 7 дней;
- пропущено 2 дня и больше — серия обнуляется, лучшая сохраняется.


## 6. Обращения в поддержку

`POST /support/tickets {topic, message, diagnostics}` → `{ticketId}`:
- `topic`:
  - `ban_appeal` — с экрана бана; должен проходить и при полном бане;
  - `support` — из настроек.
- `message`: от 1 до 1000 символов.
- `diagnostics: {appVersion, device, userId}`. `device` — одна строка, например `"ios 18.1 iPhone 15"`.

Как поддержка отвечает игроку и нужна ли очередь обращений в админке — **ждём решения продукта**.

## 7. События

По ТЗ (Часть 1 §6, Часть 7):
- событие заводится в админке: название RU/EN, даты, обложка, 5–10 карт, трек наград, связанные товары витрины;
- за карту — 10–30 токенов по звёздам, за победу на арене в период события — +5;
- одновременно не больше одного события, после конца незабранные награды выдаются автоматически;
- `GET /events/current`, `POST /events/{id}/claim {step}`;
- своей таблицы лидеров у события нет.

Экрана событий в приложении пока нет. Детали (токены за звёзды, перепрохождение, формат `reward`) — **ждём решения продукта**.

## 8. Пуши (P13–P16)

Пуши в приложении появятся после сборки на EAS. Тогда же выдадим ключ `.p8`, Team ID, Key ID и bundle id.

- **iOS** — напрямую через APNs, **Android** — через FCM HTTP v1. Клиент берёт нативный токен через `getDevicePushTokenAsync()`.
- **Регистрация токена** — ваш `PUT /me/devices/current/push-tokens`. Хранить ли токены по `provider`, как сейчас у вас, — **ждём решения продукта**.
- **У устройства нужно хранить** `tz`, `locale` и каналы `daily / friends / arena / events`.
- **Правила отправки:** не больше 2 пушей в сутки, кроме вызовов друзей; не с 22:00 до 9:00 по местному времени.

## 9. Пользовательские уровни (`/levels/custom`)

- **Кто видит:** только автор. Другим игрокам уровень передаётся кодом `PELENG2-…`, код работает без сервера.
- **Лимиты:** до 20 уровней на аккаунт (`limit_reached`), поле от 4×4 до 9×9, название до 40 символов.
- **Наград и прогресса за такие уровни нет.**
- **Контракт клиента:** тело `{level}`, ответ `{id, level, updated_at}`.

Модерация названий — **ждём решения продукта**.

Это кадр из черновика макетов, отдельного рейтинга нет. В профиле показываются кубки (`trophies`).

## Что клиент уже делает под ваши правила

- Валюта — `gems`. Нехватка — `not_enough_gems` / `not_enough_coins` с `data.need`.
- Число цветов у частей скина берётся сколько пришло.
- `Idempotency-Key` уходит во всех изменяющих запросах.
- **Страна** (`PATCH /me {country}`) пока не отправляется. Она нужна только лидерборду «Страна», а лидерборды будут отдельной задачей.
- **Арена:**
  - WebSocket только принимает события, все действия идут через REST;
  - есть фаза подготовки;
  - форматы и лиги приходят с сервера, поля бывают и прямоугольными;
  - кубки — Elo, `surrender_loss` берётся из ответа.
- **Бан арены** берётся из `GET /me.flags.bans` и из 403 на действиях.
