## 0. Что ждём от фронтенда

Без этих ответов и файлов следующие разделы бэкенд не начнёт. Номера — из вашего реестра расхождений.

**Файлы**

1. **Офлайн-кампания (K1–K10, K29, K30).** `packages/content` (уровни `c-1…c-74`, формат v2), `packages/engine/vectors/*.json` и описание правил движка, по которым считаются пеленг, «Курс» и «Горячо-холодно». Сервер переигрывает партии и должен получать тот же результат, что клиент. Сразу с этим сделаем `POST /attempts:batch`, `GET /progress` и названия режимов `distance | direction | hotcold` с полями `dir` / `cmp` (K25, K33, K34): если переименовать раньше, разъедутся уже заведённые уровни.

**Решения продукта**

2. **Значки (S4).** В макете профиля это «Достижения»: бейджи за условия (серия 7 и 30 дней, лиги Gold и Platinum, мир на 3★, уровень 25, «карта остановила 10 игроков», все уровни), закрытые показываются с условием, в профиль выбирается до 3. В витрине при этом есть тип «БЕЙДЖ». Как задумано:
   - только достижения за условия;
   - только товар витрины со слотами на 3 значка;
   - или значок — предмет витрины, который можно и купить, и получить автоматически за условие?

   Если значки остаются, пришлите список условий из ТЗ (Часть 1 §6.2, §6.4).
3. **Рекламная сеть.** Какая (Яндекс Реклама, VK Ads, AdMob…). Для `/ads/limits`, `/ads/intent` и «+3 хода» за рекламу (`method: "ad"`) награду начисляем только после серверного подтверждения просмотра (SSV) — нужны ключи и формат колбэка выбранной сети.
4. **Пункты «уточним с нашей стороны»:** награды за уровень — отдельные или общие по ТЗ (K36), нужен ли `GET /campaign/stats` (K38), экипировка `look` или `loadout` (S17), шифрование офлайн-пакетов и суточный лимит офлайн-монет (K8, K10), капча на входе и регистрации (G19).

**ТЗ для следующих разделов** (бэкенд берётся за них следующими)

5. **Дейли и серия.** Формат `/daily/{date}`, `/daily/history`, `/streak`, `/streak/restore`: как выбирается уровень дня, в каком часовом поясе меняется день (сейчас игровой день — по Москве, см. `day_key` в `/bootstrap`), награды за дни серии, цена и правила восстановления. С дейли появится и вкладка «Дейли» в лидерборде.
6. **Обращения в поддержку.** Список `topic` и поля `diagnostics`, которые отправляет клиент (версия, устройство, ОС, последние ошибки?). Ответ игроку — письмом или в приложении?
7. **События.** Что это по ТЗ: сроки, условия участия, награды, своя таблица лидеров?
8. **Пуши (P13–P16).** Имена полей устройства для `tz`, `locale` и каналов (`daily`, `friends`, `arena`, `events`). iOS — напрямую через APNs (нужен ключ `.p8`, Team ID, Key ID) или через Firebase, как сейчас?
9. **Пользовательские уровни** (`/levels/custom`): кто видит, модерация, лимиты.

**Вопросы по макетам**

10. Профиль: что за «РЕЙТИНГ 2 640 · сезон» рядом с кубками? Если это кубки в сезоне — они уже приходят в `GET /arena`; если отдельный рейтинг — нужна формула.

**Решено бэкендом — переходник на вашей стороне**

- Валюта — `gems` везде (а не `emeralds`). Коды нехватки — `not_enough_gems` / `not_enough_coins` с `data.need` (не `insufficient_funds`).
- Число цветов у частей скина не фиксировано: 1–8, один — заливка, больше — градиент. Рисуйте столько, сколько пришло.
- Страну для лидерборда отправляйте в `PATCH /me {"country": "RU"}` (по региону телефона при первом входе).
- Во всех изменяющих запросах шлите `Idempotency-Key`.

## 1. Общие правила

### Адрес

Все запросы: `{API_URL}/api/v1/...`

| Где запущено приложение | API_URL |
|---|---|
| iOS-симулятор | `http://127.0.0.1:8080` |
| Android-эмулятор | `http://10.0.2.2:8080` |
| Android по USB | `http://127.0.0.1:8080` после `adb reverse tcp:8080 tcp:8080` |
| Телефон по Wi-Fi | туннель `cloudflared tunnel --url http://127.0.0.1:8080` → `https://….trycloudflare.com` |
| Прод | только `https://` |

Адрес держи в конфиге сборки (`EXPO_PUBLIC_API_URL`), не в коде.

### Заголовки

| Заголовок | Когда | Значение |
|---|---|---|
| `Content-Type` | запросы с телом | `application/json` |
| `X-App-Version` | **каждый запрос** | версия приложения, например `1.4.2` (`expo-application` → `nativeApplicationVersion`) |
| `Authorization` | запросы с пометкой «🔒» | `Bearer <access_token>` |
| `Accept-Language` или `X-Locale` | каждый запрос | `ru` или `en`: язык `message`, техработ, окна обновления и названий. Без заголовка — русский |
| `Idempotency-Key` | изменяющие запросы с «🔒» (`POST`, `PUT`, `PATCH`, `DELETE`) | 8–128 символов: латиница, цифры, `. _ : -`. Новый ключ на каждое действие игрока, тот же — при повторе после обрыва сети (см. ниже) |
| `X-Request-Id` | по желанию | 8–64 символа: латиница, цифры, `. _ : -`. Сервер вернёт его же в ответе — по нему ищем запрос в логах. Без заголовка сервер выдаст свой |

### Повтор после обрыва сети: `Idempotency-Key`

Покупка, «+3 хода», смена ника и любые другие изменения могут оборваться так, что ответ не дошёл, а сервер уже всё сделал. Чтобы повтор не списал валюту дважды:

- на каждое нажатие игрока создай ключ (`Crypto.randomUUID()`) и шли его во всех повторах этого же действия;
- сервер сутки помнит ключ и ответ: повтор с тем же телом вернёт сохранённый ответ (с заголовком `Idempotent-Replayed: true`), даже если это была ошибка;
- тот же ключ с другим телом — 409 `idempotency_mismatch` (ошибка в коде);
- пока первый запрос ещё выполняется — 409 `idempotency_in_progress` с `Retry-After: 1`: подожди и повтори;
- ответы 5xx не сохраняются: такой запрос можно повторить с тем же ключом.

### Время

Все даты в ответах — RFC 3339 в UTC с `Z`, например `2026-11-04T16:00:00Z`. Таймеры считай от `server_time` в ответе, а не от часов телефона.

### Формат ответа

Успех — всегда `success: true`, данные в `data` (у некоторых запросов `data` нет):

```json
{ "success": true, "data": { ... } }
```

Ошибка — `success: false`:

```json
{
  "success": false,
  "code": "validation_failed",
  "message": "Проверьте правильность заполнения.",
  "errors": { "email": "Введите корректный email, например name@mail.ru." }
}
```

| Поле | Что это |
|---|---|
| `code` | машинный код. **По нему приложение решает, что делать** (не по `message`) |
| `message` | готовый текст на языке из `Accept-Language` (`ru` или `en`), можно показать игроку |
| `errors` | ошибки по полям: ключ = имя поля в запросе. Показывай под полем |
| `data` | дополнительные данные (например, окно обновления при 426) |

### Общие ошибки любого запроса

| HTTP | code | Когда | Что делать |
|---|---|---|---|
| 400 | `invalid_json` | тело пустое, не JSON или несколько объектов | ошибка в коде приложения |
| 400 | `invalid_app_version` | `X-App-Version` не похож на версию | ошибка в коде приложения |
| 413 | `body_too_large` | тело больше лимита | ошибка в коде приложения |
| 422 | `validation_failed` | поля не прошли проверку, детали в `errors` | показать `errors` под полями. Лишнее поле в JSON тоже даёт эту ошибку: «Такого поля нет.» |
| 426 | `app_update_required` | версия ниже минимальной | окно обновления из `data` (раздел 2) |
| 429 | `too_many_requests` | слишком часто | подождать `Retry-After` секунд (заголовок), заблокировать кнопку |
| 503 | `maintenance` | техработы | экран техработ: в `data` — `{until, message}`, заголовок `Retry-After` |
| 403 | `banned` | игрок ограничен | в `data` — `{scope, until, reason}`: `scope: "all"` — экран блокировки (доступны только профиль, выход и удаление аккаунта), `"arena"` — закрыта только арена; `until: null` — бессрочно |
| 500 | `internal_error` | сбой на сервере | «Что-то пошло не так», дать повторить |

Запросы с «🔒» дополнительно могут вернуть 401 — раздел 4.

### Общие правила полей

| Поле | Правило | Текст ошибки в `errors` |
|---|---|---|
| `email` | обязательно, формат `имя@домен.зона`, до 254 символов; регистр и пробелы по краям не важны | «Введите корректный email, например name@mail.ru.» |
| `password` (новый) | 8–128 символов; буквы и хотя бы одна цифра или символ; не из списка популярных; без последовательностей (`12345`, `qwerty`, `abcd`, `йцукен`) и повторов; без email и ника внутри | один из текстов: «Пароль должен быть от 8 до 128 символов.», «Пароль должен содержать буквы и хотя бы одну цифру или символ.», «Слишком распространённый пароль, его легко подобрать.», «Пароль слишком простой: последовательности вроде 12345, qwerty или abcd легко подобрать.», «Пароль не должен содержать email или ник.» |
| `nickname` | 3–16 символов: латиница, цифры и `_`. Уникален без учёта регистра: занят — 409 `nick_taken` | «Ник: от 3 до 16 символов — латиница, цифры и _» |
| `code` | ровно 6 цифр | «Код — 6 цифр.» |
| `device` | объект, см. ниже | — |

В форме проверяй заранее длину и формат (удобно игроку), но **окончательно решает сервер**: тексты сложности пароля показывай из `errors.password` как есть.

### Объект `device`

Передаётся при входе и подтверждении регистрации.

| Поле | Обязательно | Правило |
|---|---|---|
| `device_id` | да | 8–128 символов: латиница, цифры, `. _ : -`. Создаётся один раз на установку и не меняется |
| `platform` | да | `ios`, `android` или `web` |
| `name` | нет | до 100 символов, например `iPhone 15` |
| `app_version` | нет | до 32 символов |

```ts
import * as SecureStore from 'expo-secure-store';
import * as Crypto from 'expo-crypto';
import * as Device from 'expo-device';
import * as Application from 'expo-application';
import { Platform } from 'react-native';

export async function getDevice() {
  let id = await SecureStore.getItemAsync('device_id');
  if (!id) {
    id = Crypto.randomUUID();
    await SecureStore.setItemAsync('device_id', id);
  }
  return {
    device_id: id,
    platform: Platform.OS === 'ios' ? 'ios' : 'android',
    name: Device.modelName ?? undefined,
    app_version: Application.nativeApplicationVersion ?? undefined,
  };
}
```

У игрока не больше 20 устройств: при входе с 21-го самое старое разлогинивается само.

### Лимиты

- Запросы регистрации, входа и восстановления пароля ограничены по IP. При превышении 429 с заголовком `Retry-After`.
- После 5 неверных паролей подряд вход для этого email блокируется на 15 минут (429).
- Код из письма: живёт 15 минут, 5 попыток ввода, повторная отправка не чаще раза в 60 секунд, не больше 10 писем в сутки на email.

## 2. Приложение: техработы, версия, документы

### `GET /bootstrap` — стартовые данные

Без токена, работает и во время техработ. Вызывай при запуске первым.

```json
{
  "server_time": "2026-11-04T16:00:00Z",
  "config": {
    "arena.maxTurns": 60,
    "ads.interstitial.everyN": 3, "ads.interstitial.minIntervalSec": 90, "ads.interstitial.minLevel": 5,
    "features.daily": true, "features.friends": false
  },
  "ads_network": "yandex",
  "content_version": "4f2a91c0d3e8",
  "day_key": "2026-11-04",
  "next_day_at": "2026-11-04T21:00:00Z",
  "maintenance": null
}
```

| Поле | Что это |
|---|---|
| `config` | удалённые настройки из админки. Флаги `features.*` — только те, что заведены; нет ключа — поведение по умолчанию |
| `ads_network` | рекламная сеть; пустая строка — реклама выключена |
| `content_version` | меняется при любой правке уровней и миров: другая версия — обнови кеш кампании |
| `day_key`, `next_day_at` | текущие игровые сутки и когда начнутся следующие (часовой пояс задаётся в админке) |
| `maintenance` | не `null` — идут техработы, как в `/maintenance` |

### `GET /maintenance` — идут ли техработы

Отвечает всегда, даже во время техработ.

```json
{ "success": true, "data": null }
```
`data: null` — всё работает. Иначе:
```json
{ "success": true, "data": { "until": "2026-11-04T18:00:00Z", "message": "Ведутся технические работы. Попробуйте зайти чуть позже." } }
```

| Поле | Что это |
|---|---|
| `until` | примерное окончание; `null` — без срока |
| `message` | текст на языке из `Accept-Language` |

Остальные запросы во время техработ получают `503 maintenance` с тем же `data` и заголовком `Retry-After`.

### `GET /version` — нужно ли обновиться

Вызывать при запуске после `/bootstrap`, с заголовком `X-App-Version`. Тексты окна — на языке из `Accept-Language`.

**Ответ 200**
```json
{
  "success": true,
  "data": {
    "show_modal": true,
    "force_update": false,
    "min_version": "1.2.0",
    "current_version": "1.4.0",
    "title": "Обновите приложение",
    "description": "Мы обновили приложение, пожалуйста, скачайте новую версию.",
    "button_text": "Обновить",
    "ru_store": "https://www.rustore.ru/catalog/app/...",
    "play_market": "",
    "app_store": ""
  }
}
```

| Ситуация | `show_modal` | `force_update` | Что показать |
|---|---|---|---|
| версия ниже `min_version` | `true` | `true` | окно без кнопки «Позже», дальше не пускать |
| версия ниже `current_version` | `true` | `false` | окно, которое можно закрыть |
| версия актуальная или заголовка нет | `false` | `false` | ничего |

Ссылку на магазин бери по платформе: iOS → `app_store`, Android → `play_market` или `ru_store` (откуда установлено). Пустая строка — ссылки нет.

**Ошибки:** `400 invalid_app_version`, `503 maintenance`.

Если версия ниже минимальной, **любой** другой запрос вернёт `426 app_update_required`, в `data` те же поля, что у `/version`.

### `GET /document?type=…` — документ PDF

Отдаёт документ, загруженный в админке, **сразу файлом PDF**, без JSON-обёртки. Работает без токена, без `X-App-Version` и даже во время техработ.

| `type` | Документ |
|---|---|
| `privacy_policy` | политика конфиденциальности |
| `terms` | условия использования |

Английская версия: добавь `&lang=en` (или пришли `Accept-Language: en`) — сервер отдаст документ `<type>_en`, если он загружен, иначе русский. Ключи заводятся в админке («Документы»).

**Ответ 200:** тело — сам PDF.

| Заголовок | Значение |
|---|---|
| `Content-Type` | `application/pdf` |
| `Content-Disposition` | `inline; filename="privacy_policy.pdf"` |
| `Cache-Control` | `public, max-age=300` |

**Ошибки** (обычным JSON): `400 invalid_document_type`, `404 document_not_found` (документ ещё не загружен), `429 too_many_requests`.

Как показать в приложении:

- **Внутри приложения** — `react-native-pdf`, он сам скачивает и кеширует файл:
  ```tsx
  import Pdf from 'react-native-pdf';

  <Pdf
    source={{ uri: `${API_URL}/document?type=privacy_policy`, cache: true }}
    trustAllCerts={false}
    onError={() => setFailed(true)}
  />
  ```
  `WebView` для этого не подходит: на Android он не умеет показывать PDF.
- **Во внешнем браузере** — `Linking.openURL(`${API_URL}/document?type=privacy_policy`)`. Эту же ссылку указываем в Google Play, App Store и RuStore.
- **Скачать как blob** (например, чтобы сохранить или поделиться):
  ```ts
  const res = await fetch(`${API_URL}/document?type=privacy_policy`);
  if (!res.ok) throw new Error((await res.json()).code);
  const pdf = await res.blob();
  ```
  Через `axios` из раздела 10 не скачивай: он ждёт JSON. Если всё же нужен axios, передай `responseType: 'blob'`.

## 3. Регистрация

Три шага: отправить данные → получить код на почту → ввести код (игрок сразу входит).

### `POST /auth/register` — шаг 1

**Тело**
```json
{
  "email": "user@example.com",
  "password": "лесная тропа 7",
  "nickname": "star_runner",
  "accept_terms": true,
  "accept_privacy": true,
  "accept_marketing": false
}
```

| Поле | Обязательно | Правило |
|---|---|---|
| `email` | да | общее правило |
| `password` | да | правило нового пароля (не содержит email и ник) |
| `nickname` | да | общее правило |
| `accept_terms` | да | только `true`, иначе «Нужно принять, чтобы продолжить.» |
| `accept_privacy` | да | только `true` |
| `accept_marketing` | нет | согласие на рассылки, по умолчанию `false` |

**Ответ 202**
```json
{ "success": true, "data": { "resend_after": 60 } }
```
`resend_after` — через сколько секунд можно запросить код повторно (таймер на кнопке).

Ответ одинаковый, даже если email уже занят: так нельзя узнать, кто зарегистрирован. Владельцу занятого адреса придёт письмо «вы уже зарегистрированы». Поэтому после 202 **всегда** открывай экран ввода кода.

**Ошибки:** `422 validation_failed`, `429 too_many_requests`.

### `POST /auth/register/resend` — отправить код ещё раз

**Тело:** `{ "email": "user@example.com" }`

**Ответ 202:** `{ "success": true, "data": { "resend_after": 60 } }` — тоже одинаковый для любого email.

**Ошибки:** `422 validation_failed`, `429 too_many_requests`.

### `POST /auth/register/verify` — шаг 3, ввод кода

**Тело**
```json
{ "email": "user@example.com", "code": "123456", "device": { "device_id": "...", "platform": "ios" } }
```

**Ответ 200** — пара токенов (раздел 4), игрок вошёл.

**Ошибки**

| HTTP | code | Поле | Что делать |
|---|---|---|---|
| 422 | `invalid_code` | `errors.code` | неверный или просроченный код, показать под полем |
| 422 | `too_many_attempts` | `errors.code` | 5 неверных попыток: предложить «Отправить код ещё раз» |
| 422 | `validation_failed` | разные | показать под полями |

## 4. Вход, токены, выход

### `POST /auth/login` — вход по почте и паролю

**Тело**
```json
{ "email": "user@example.com", "password": "...", "device": { "device_id": "...", "platform": "android" } }
```

| Поле | Правило |
|---|---|
| `email` | общее правило |
| `password` | обязательно, до 128 символов (сложность при входе не проверяется) |
| `device` | объект устройства |

**Ответ 200 — пара токенов**
```json
{
  "success": true,
  "data": {
    "access_token": "eyJhbGciOi...",
    "token_type": "Bearer",
    "expires_in": 900,
    "refresh_token": "q2xv0Yk3...",
    "refresh_expires_in": 2592000,
    "session_id": "6f1c..."
  }
}
```

| Поле | Что это |
|---|---|
| `access_token` | идёт в `Authorization: Bearer ...`, живёт `expires_in` секунд (15 минут) |
| `refresh_token` | обменивается на новую пару, живёт 30 дней, **одноразовый** |
| `session_id` | id сессии (для отладки) |

**Ошибки**

| HTTP | code | Что делать |
|---|---|---|
| 401 | `invalid_credentials` | «Неверный email или пароль» (сервер не говорит, что именно неверно) |
| 403 | `email_not_verified` | почта не подтверждена: вызвать `/auth/register/resend` и открыть экран кода |
| 429 | `too_many_requests` | много попыток, ждать `Retry-After` |
| 422 | `validation_failed` | показать под полями |

### `POST /auth/refresh` — обновить токены

**Тело:** `{ "refresh_token": "q2xv0Yk3..." }`

**Ответ 200** — новая пара токенов. **Сразу сохрани её**: старый refresh больше не работает.

**Ошибки (все — выйти на экран входа и удалить токены)**

| HTTP | code | Что случилось |
|---|---|---|
| 401 | `invalid_refresh_token` | токен истёк или неизвестен |
| 401 | `refresh_token_reused` | старый refresh использован повторно — сервер считает это кражей и завершает сессию |
| 401 | `session_revoked` | сессию завершили (выход, смена пароля, удаление устройства) |

> **Важно.** Refresh должен выполняться **строго один раз за раз**. Если два запроса одновременно получили 401 и оба отправили один и тот же refresh, второй получит `refresh_token_reused`, и игрока выкинет. В клиенте из раздела 10 это решено: обновление идёт одним запросом, остальные ждут его.

### 401 на запросах с «🔒»

| code | Что делать |
|---|---|
| `unauthenticated` | нет заголовка `Authorization` — приложение не вошло |
| `invalid_token` | access истёк или повреждён — один раз сделать refresh и повторить запрос |
| `session_revoked` | сессия завершена — на экран входа |

### `POST /auth/logout` 🔒 — выйти на этом устройстве

Без тела. **Ответ 200:** `{ "success": true }`. Удали токены локально, даже если запрос не прошёл.

### `POST /auth/logout-all` 🔒 — выйти на всех устройствах

Без тела. **Ответ 200:** `{ "success": true }`.

**Тело:** любое из полей — `{ "nickname": "new_nick", "locale": "en", "country": "RU" }`.

| Поле | Правило |
|---|---|
| `nickname` | общее правило ника. Первая смена бесплатно, вторая и дальше — за ◆ (`nickname_change.price`), третья и дальше — не чаще раза в 30 дней (`nickname_change.available_at`) |
| `locale` | `ru` или `en` |
| `country` | две заглавные латинские буквы (`RU`, `KZ`); `""` — убрать. Определи по региону телефона при первом входе и дай поменять в настройках |

**Ответ 200** — профиль. **Ошибки:** `409 nick_taken` (`errors.nickname`), `409 nick_change_cooldown` (в `data` — `available_at`), `409 not_enough_gems` (в `data` — `need`), `422 validation_failed`. Шли `Idempotency-Key`: смена ника платная.

|---|---|
| `email` | общее правило |
| `password` | текущий пароль, обязателен, если пароль есть |

**Ошибки:** `422 same_email` (`errors.email`: это уже ваш email), `422 password_required` / `wrong_password` (`errors.password`), `403 reauth_required`, `429 too_many_requests` (повторная отправка раньше `resend_after`).

**Тело:** `{ "code": "123456" }`

**Ответ 200** — профиль с новым email. На старый адрес уходит уведомление о смене.

**Тело:** `{ "password": "текущий пароль" }` (обязателен, если пароль есть).


**Ошибки:** `422 password_required` / `wrong_password` (`errors.password`), `403 reauth_required`.

### `POST /me/restore` — отменить удаление

**Ответ 200** — профиль без `flags.deletion_scheduled_at`. **Ошибки:** `409 not_scheduled` — удаление не запрошено.

## 8. Кампания: уровни, игра, награды

Главное правило: **где цели, бомбы и буи — знает только сервер**. Приложение получает раскладку без них и открывает клетку тапом. Победу, звёзды и монеты считает сервер. Никогда не показывай игроку то, чего нет в ответе.

Все запросы раздела — 🔒, с `Accept-Language: ru` или `en` (от него зависят названия).

### `GET /campaign` 🔒 — главная и список уровней

```json
{
  "stars": 74, "stars_max": 300, "levels_done": 26, "perfect": 18, "coins_earned": 940,
  "current_level": 27, "completed": false,
  "unlocks": { "daily_level": 6, "arena_level": 12, "daily": true, "arena": true },
  "known_elements": ["bomb", "bridge", "fence", "stream"],
  "tutorials": ["tut_first_level", "tut_bomb"],
  "active": { "game_id": "…", "level": 27, "found": 1, "total": 2 },
  "wallet": { "coins": 340, "gems": 25 },
  "worlds": [{
    "number": 3, "title": "Мины", "subtitle": "новое: бомба и значок мины",
    "color_from": "#5a2230", "color_to": "#ff8a6a",
    "first_level": 25, "last_level": 40, "stars": 5, "stars_max": 48, "state": "current",
    "levels": [{
      "number": 25, "title": "Первая мина", "description": "7×7 · 1 бомба",
      "rows": 7, "cols": 7, "mode": "number", "elements": ["bomb", "stream", "bridge"], "introduces": ["bomb"],
      "tutorial": "tut_bomb", "state": "perfect", "stars": 3, "best_moves": 8,
      "rewards": [20, 30, 50], "coins_earned": 50
    }]
  }]
}
```

| Поле | Что с ним делать |
|---|---|
| `current_level` | баннер «Играть» на главной; `0` и `completed: true` — кампания пройдена |
| `active` | незаконченная партия текущего уровня: «ПРОДОЛЖИТЬ», «найдено 1 / 2» |
| `unlocks` | пеленг дня и арена: замок «Откроется после уровня N», пока `false` |
| `known_elements` | список «Правил» в паузе: только встреченные элементы |
| `tutorials` | обучения и карточки, которые игрок уже видел — повторно не показывать |
| `worlds[].state` | `locked` — серый и свёрнутый, `current`, `done`, `perfect` — золотая рамка |
| `levels[].state` | `locked` — тап: тряска и тост, `current` — «Играть», `done`, `perfect` (3★) |
| `levels[].mode` | режим подсказки уровня: `number`, `hot_cold` или `course` — подпись на карточке уровня |
| `levels[].rewards` | ● за уровень всего на 1★ / 2★ / 3★ — у каждого уровня свои. На листе уровня и в победе: «Награда ● 50» |
| `levels[].coins_earned` | сколько ● игрок уже забрал за уровень. Ещё можно получить `rewards[2] − coins_earned`; `0` — показывай «награда получена» |
| `levels_done`, `perfect`, `coins_earned` | итог по уровням: пройдено, из них на 3★, монет за уровни |
| `levels[].introduces` | перед уровнем — карточки этих элементов (если их нет в `tutorials`) |
| `levels[].tutorial` | ключ сценария обучения в приложении |
| `color_from`, `color_to` | градиент обложки мира |

Элементы: `fence`, `stream`, `bridge`, `heavy` (×2), `rock`, `multi_target`, `bomb`, `mine_mark`, `beacon`, `buoy`, `fog`, `order`, `hot_cold`, `course`. Значки и тексты карточек — в приложении.

### Режимы подсказки

Каждый уровень работает в одном режиме — его задаёт админка. Поле строится одинаково, разница только в том, что показывает открытая клетка (`number`, `beacon`, `buoy`):

| `mode` | В клетке | Поля клетки |
|---|---|---|
| `number` | число шагов до сигнала, цвет по `tone` | `value`, `tone` |
| `hot_cold` | ↑ теплее, ↓ холоднее, = так же, — первый тап | `compare`: `warmer`, `colder`, `same`, `none` |
| `course` | стрелка к соседней клетке, откуда до сигнала ближе; цвет по `tone`, при `hot` — пульсирует | `direction`: `up`, `right`, `down`, `left`; `tone` |

Сервер отдаёт **только** поля своего режима: в `hot_cold` и `course` числа нет вовсе — не пытайся его показывать или вычислять.

- `hot_cold`: сравнение с прошлым **открытым числом** (буй тоже число). Бомба сравнение не сбрасывает, найденная цель — сбрасывает: следующий тап снова `none`. Маяки всегда `none`.
- `course`: из четырёх соседей (вверх, вправо, вниз, влево) без скал и без соседей за забором выбирается тот, откуда до ближайшей оставшейся цели меньше шагов (сама ненайденная цель считается на 1 ближе). При равенстве — первый по порядку вверх → вправо → вниз → влево.
- Подсказка по тапу на открытую клетку: `number` — «D4: пеленг 3», `hot_cold` — «D4: теплее», `course` — «D4: курс ←».

### `GET /campaign/levels/{number}` 🔒 — лист «Уровень N»

То же, что строка уровня, плюс `board` — публичная раскладка для превью:

```json
"board": {
  "rows": 7, "cols": 7,
  "terrain": ["...s...", "...s...", "...b...", "...s...", "...s...", ".......", "r.....h"],
  "fences": [[[1,4],[2,4]]], "beacons": [[0,0]], "mode": "number",
  "fog": 0, "order": false, "limit": 14, "stars": [9, 11],
  "targets": 2, "bombs": 1, "buoys": 0
}
```

`terrain` — строки поля: `.` обычная, `s` ручей, `b` мост, `h` ×2, `r` скала. `fences` — пары соседних клеток `[строка, столбец]`. `stars: [9, 11]` — 3★ за ≤ 9 ходов, 2★ за ≤ 11. `limit: 0` — без лимита (обучение, всегда 3★). `targets`, `bombs`, `buoys` — только количество.

### `POST /campaign/levels/{number}/play` 🔒 — играть

Тело необязательно: `{ "restart": true }` — начать заново. Без него вернётся незаконченная партия («партия сохранится»).

Ответ — **партия**:
```json
{
  "id": "…", "level": 25, "version": 3, "seq": 5, "status": "play",
  "board": { "…": "как выше" },
  "moves": 5, "limit": 14, "found": 1, "bombs_left": 1, "epoch": 1, "continues": 0,
  "cells": [
    { "row": 0, "col": 0, "kind": "beacon", "value": 4, "tone": "warm", "epoch": 0 },
    { "row": 3, "col": 4, "kind": "number", "value": 3, "tone": "warm", "near_bomb": true, "epoch": 0 },
    { "row": 1, "col": 5, "kind": "target", "order": 1, "epoch": 0 },
    { "row": 2, "col": 2, "kind": "bomb", "epoch": 0 }
  ]
}
```

| Поле | Что это |
|---|---|
| `seq` | сколько тапов сделано — передавай в следующем тапе |
| `limit` | лимит с бонусами буёв и «+3 хода»; `0` — без лимита |
| `bombs_left` | счётчик невзорванных бомб в шапке |
| `epoch` | клетки с `epoch` меньше этого — «устаревшие» (найдена цель): показывай серыми |
| `cells[].kind` | `number`, `beacon` (открыт с начала), `buoy` (+3 хода), `target`, `bomb` |
| `cells[].near_bomb` | значок мины в углу |

У `number`, `beacon` и `buoy` есть подсказка по режиму уровня (`board.mode`): `value` + `tone`, `compare` или `direction` + `tone` — см. «Режимы подсказки». У `target` и `bomb` подсказки нет.

Туман (`board.fog = N`) — приложение само прячет все числа, кроме N последних (по порядку в `cells`).

### `POST /campaign/games/{id}/tap` 🔒 — тап

```json
{ "row": 3, "col": 4, "seq": 5 }
```

Ответ: `{ "cell": { …открытая клетка… }, "game": { …партия… } }`. Показывай `cell` с анимацией, остальное бери из `game`.

| Ошибка | Что делать |
|---|---|
| `409 stale_game` | ответ на прошлый тап потерялся, и ты повторил его. В `data` — свежая партия: перерисуй поле и не повторяй тап |
| `409 cell_open` | клетка уже открыта — покажи подсказку «D4: пеленг 3» локально, запрос не нужен |
| `409 game_over` | партия закончена — покажи итог |
| `422 invalid_cell` | скала или клетка за полем — по ним тапать не давай |

Когда `game.status` стал `won` или `lost`, в `game.result`:

```json
{
  "stars": 3, "moves": 8, "best_moves": 7, "new_record": false, "reward": 50, "xp": 10, "world_gems": 35,
  "next_level": 26,
  "secrets": { "targets": [[1,5],[5,1]], "bombs": [[2,2]], "buoys": [] },
  "wallet": { "coins": 390, "gems": 25 },
  "can_continue": false, "continue_cost": 15
}
```

- **Победа:** звёзды, ходы, рекорд, `reward` — сколько ● начислено сейчас. За уровень всего платится не больше `rewards` за набранные звёзды: 1★ дала 20, потом 3★ — ещё 30 (итог 50). Повторная победа на те же звёзды — ● 5. `xp` — опыт за партию (10 за первую победу, 2 за повторную). `world_gems` — ◆ за пройденный мир (10) и за все 3★ в мире (25), один раз. `secrets` — показать оставшиеся бомбы.
- Номер цели (`order` в клетке) приходит только на уровнях с порядком целей.
- **Поражение (`lost`):** `can_continue` и `continue_cost` — кнопка «+3 хода за ◆ 15». `secrets` нет, пока игрок не откажется.

### `POST /campaign/games/{id}/continue` 🔒 — «+3 хода» за ◆

`{ "seq": 12 }`. Изумруды списывает сервер. Ответ — партия со статусом `play` и лимитом +3. После продолжения победа — максимум 1★. Ошибки: `409 not_enough_gems` (в `data.need` — сколько не хватает; открой «Как заработать»), `409 cannot_continue`.

### `POST /continue` 🔒 — «+3 хода» по `attempt_id`

```json
{ "attempt_id": "<id партии>", "method": "emeralds" }
```
Ответ: `{ "granted": true, "bonus_moves": 3, "wallet": { "coins": 340, "gems": 10 } }`. Шли `Idempotency-Key`. Одно продолжение на партию. `method: "ad"` пока отвечает 422 `continue_method`: продолжение за рекламу появится с проверкой просмотра на сервере. Ошибки: `409 not_enough_gems` (в `data.need` — сколько не хватает), `409 cannot_continue`.

### `POST /campaign/games/{id}/give-up` 🔒 — «Не продолжать»

Закрывает проигранную партию. В `result.secrets` — где были цели и бомбы (показать полупрозрачно).

### `GET /campaign/games/{id}` 🔒 — партия целиком (после перезапуска приложения)

### `POST /campaign/tutorials` 🔒 — обучение пройдено

`{ "key": "tut_bomb" }` — сценарий обучения (`levels[].tutorial`), `{ "key": "bomb" }` — карточка элемента (ключ из `levels[].introduces`). Ключ попадёт в `tutorials` на любом устройстве. Другие ключи сервер не примет: 422 `validation_failed`.

### `GET /campaign/stats` 🔒 — блок «Статистика» в профиле

```json
{ "levels_done": 27, "levels_total": 100, "stars": 74, "stars_max": 300, "perfect": 18, "coins_earned": 940 }
```

Плитки «Уровни» (`levels_done`) и «Звёзды» (`stars`). Победы, пик кубков и защита появятся вместе с PvP, серия — вместе с ежедневными наградами.

### `GET /wallet` 🔒 — баланс

`{ "coins": 390, "gems": 25 }` — ● и ◆. Баланс меняет только сервер.

### Игра без сети

1. **Пока сеть есть** — после входа и после каждой синхронизации:
   `POST /campaign/offline/pack` 🔒 →
   ```json
   {
     "pack_id": "…", "expires_at": "2026-11-01T12:00:00Z", "alg": "A256GCM", "key": "base64…",
     "levels": [{ "number": 27, "version": 3, "nonce": "base64…", "data": "base64…" }]
   }
   ```
   Это текущий и следующие уровни (по умолчанию 10). Каждый зашифрован AES-256-GCM. **Ключ храни только в защищённом хранилище** (`expo-secure-store` → Keychain / Keystore), сами уровни — в обычном кеше зашифрованными. Расшифровывай уровень только перед игрой, в памяти. Не чаще 20 наборов в сутки.

2. **Расшифровка** (например, `react-native-quick-crypto`):
   ```ts
   const aad = `${pack.pack_id}:${l.number}:${l.version}`;
   const decipher = crypto.createDecipheriv('aes-256-gcm', key, nonce);
   decipher.setAAD(Buffer.from(aad));
   decipher.setAuthTag(data.subarray(data.length - 16));
   const json = Buffer.concat([decipher.update(data.subarray(0, data.length - 16)), decipher.final()]);
   ```
   Внутри — `{ number, version, world, title, description, tutorial, introduces, level }`, где `level` — полная раскладка с целями. Если расшифровка не удалась, уровень испорчен или подменён — удали набор и возьми новый.

3. **Без сети** игра идёт по тем же правилам на телефоне (движок из прототипа). Режим подсказки — `level.mode` внутри расшифрованного уровня; стрелку и «теплее/холоднее» считай по правилам из «Режимы подсказки», иначе сервер при синхронизации не сойдётся с тем, что видел игрок. Сохраняй каждую партию: случайный `id` (UUID), `pack_id`, `level`, `version`, тапы `[[строка, столбец], …]`, `started_at`, `finished_at`. Звёзды показывай сразу, монеты — «зачислим при подключении». «+3 хода» и реклама без сети недоступны.

4. **Когда сеть вернулась:**
   `POST /campaign/offline/sync` 🔒 `{ "results": [ … до 30 партий … ] }` →
   ```json
   { "results": [{ "id": "…", "status": "won", "stars": 3, "reward": 50 }], "wallet": { "coins": 440, "gems": 25 } }
   ```
   Сервер переигрывает каждую партию сам. Повтор того же `id` безопасен. Отклонённые (`status: rejected`, `reason`) — убери из очереди, звёзды по ним не засчитаны. Монеты за офлайн-партии ограничены в сутки. Затем снова возьми свежий набор.

### Награды (настраиваются в админке)

| Что | По умолчанию |
|---|---|
| ● за 1★ / 2★ / 3★ | задаётся в каждом уровне; новый уровень получает 20 / 30 / 50 из настроек |
| ● за повторную победу | 5 |
| ◆ за пройденный мир / все 3★ в мире | 10 / 25 |
| Опыт за первую / повторную победу | 10 / 2 |
| Пороги цвета «горячо» / «тепло» | 20 % / 45 % от расстояния до самой дальней клетки |
| «+3 хода» | ◆ 15, одно за партию |
| ● за офлайн-партии в сутки | не больше 300 |
| Пеленг дня / арена открываются | после уровня 6 / 12 |

Реклама «Удвоить» и «+3 хода за рекламу» появятся вместе с подключением рекламной сети: награду за рекламу сервер начисляет только по подтверждению от сети.

## 9. Витрина: косметика за монеты и изумруды

Косметика меняет только вид: поле, элементы, эффекты и профиль. На результат игры она не влияет. Все товары заводятся в админке, приложение ничего не хардкодит: список, цены, сроки и цвета приходят с сервера. ● — монеты (`coins`), ◆ — изумруды (`gems`).

### `GET /shop` 🔒 — витрина

```json
{
  "server_time": "2026-10-31T12:00:00Z",
  "wallet": { "coins": 18420, "gems": 2640 },
  "featured": { "key": "set_storm", "...": "тот же формат, что у товара" },
  "tabs": [{ "key": "exclusive", "title": "Эксклюзив", "count": 2 }, { "key": "holiday", "title": "Праздничное", "count": 2 }],
  "items": [{
    "key": "night", "tab": "exclusive", "kind": "board", "kind_title": "Поле",
    "title": "Ночной сигнал", "description": "Неон, вода и светящийся забор.",
    "rarity": "legendary", "rarity_title": "Легендарный",
    "currency": "gems", "price": 1680, "owned": false, "equipped": false,
    "ends_at": "2026-11-06T02:00:00Z",
    "image": "/shop/images/3f2a….png", "render": "textures",
    "style": { "bg": ["#1f3f7a", "#070f24"], "cell": ["#2c4f8f", "#1b3566"], "number": ["#0f2148"] },
    "textures": { "bg": "/shop/files/a1….png", "cell": "/shop/files/b2….png", "open": "/shop/files/c3….png" },
    "single_theme": false,
    "dark": {
      "style": { "bg": ["#070f24"], "cell": ["#16264a", "#0d1a36"], "number": ["#eaf2ff"] },
      "textures": { "bg": "/shop/files/d4….png", "cell": "/shop/files/e5….png", "open": "/shop/files/f6….png" }
    }
  }, {
    "key": "set_storm", "tab": "bundles", "kind": "bundle", "price": 450, "full_price": 1500, "stock_limit": 500, "stock_left": 37,
    "parts": ["creek", "fence_neon", "sparks"], "parts_owned": ["creek"], "owned": false
  }]
}
```

| Поле | Что с ним делать |
|---|---|
| `tabs` | вкладки по порядку: `exclusive`, `holiday`, `elements`, `boards`, `bundles`, `profile`, `effects`. `count` — товаров в продаже |
| `featured` | баннер LIMITED DROP вверху, всегда с `ends_at` для таймера; нет поля — баннер не показывать |
| `kind` | тип товара и слот, куда он надевается (таблица «Слоты» ниже). `bundle` — набор, не надевается |
| `rarity` | цвет рамки карточки: `common`, `rare`, `epic`, `legendary`, `exclusive` |
| `ends_at` | таймер на карточке. Считай от `server_time`, не от часов телефона. Нет поля — товар продаётся всегда |
| `owned`, `equipped` | «Скрыть купленное», кнопки «Купить» / «Надеть» / «Надето ✓». У набора `owned` — собран целиком |
| `default` | базовый предмет: есть у всех бесплатно, надет, пока игрок не выбрал другой. Базовые предметы заводят в админке, по одному на слот |
| `layer_colors` | только у `lottie`: перекраска слоёв анимации, имя слоя → цвет (см. «Как рисовать») |
| `price`, `full_price` | у набора цена уже пересчитана: цена уже купленных частей вычтена, но не ниже 30 % цены набора. Тогда `full_price` — цена набора без уменьшения (зачёркнутая). Если ничего не куплено, `full_price` — зачёркнутая цена из админки, если задана |
| `stock_limit`, `stock_left`, `sold_out` | тираж: сколько всего и сколько осталось. `sold_out: true` — продано, кнопку «Купить» не показывать |
| `single_theme`, `dark` | поля верхнего уровня (`style`, `textures`, `animation`, `layer_colors`) — светлая тема. `dark` — тёмная тема в том же формате. `single_theme: true` — `dark` нет, рисуй светлую в обеих темах |
| `parts_owned` | в составе набора пометить «уже есть» |
| `image` | путь от адреса API: `${API_URL}${image}`. По адресу содержимое не меняется — кешируй навсегда |
| `render` | как рисовать предмет: `colors` — по `style`, `textures` — картинками из `textures`, `lottie` — анимацией из `animation` (раздел «Как рисовать» ниже) |
| `style` | цвета частей предмета (таблица «Части предмета»): часть → список hex. Один цвет — сплошная заливка, два и больше — градиент в этом порядке. Части без цветов не приходят — их рисуй как в базовом предмете слота |
| `loop` | у `lottie`: `true` — анимация идёт по кругу (вода, свечение, фон), нет поля — проигрывается один раз по событию (тап, находка, победа) |
| `textures`, `animation` | адреса файлов от адреса API, содержимое по адресу не меняется — кешируй навсегда |
| `min_app_version` | товар требует версию не ниже. Отправляй `X-App-Version` — тогда сервер сам скроет то, что эта версия не умеет рисовать |

### Слоты: что где меняется

В каждом слоте надет один предмет: купленный или базовый. Базовый вид игры — это тоже предметы из админки, у всех одинаковые. Пустой слот (`""` в `equipped`) бывает, только пока базовый предмет для слота не заведён: рисуй его цветами по умолчанию из таблицы ниже, эффект не проигрывай.

| Слот | Вкладка | Что меняет | Где видно |
|---|---|---|---|
| `board` | Поля | поле целиком: фон, клетки | кампания, арена |
| `fence` | Элементы | заборы между клетками | кампания, арена |
| `stream`, `bridge` | Элементы | ручьи и мосты | кампания, арена |
| `heavy`, `rock` | Элементы | клетки ×2 и скалы | кампания, арена |
| `bomb` | Элементы | бомба после взрыва | кампания, арена |
| `buoy`, `beacon` | Элементы | буи и маяки | кампания, арена |
| `marker` | Элементы | маркер найденной цели | кампания, арена |
| `number` | Эффекты | стиль цифр в открытых клетках | кампания, арена |
| `tap` | Эффекты | анимация нажатия на клетку | кампания, арена |
| `reveal` | Эффекты | анимация, когда найдена цель | кампания, арена |
| `win` | Эффекты | анимация на экране победы | кампания, арена |
| `avatar`, `frame`, `title` | Профиль | аватар, рамка и титул | профиль, карточка в дуэли |

Эксклюзив и Праздничное — те же слоты, только с таймером. На арене соперник видит то, что надето у игрока в профиле: это придёт вместе с матчем, когда сделаем PvP.

### Как рисовать: цвета, текстуры, Lottie

Приложение один раз умеет три способа — дальше любые новые скины и эффекты заводятся в админке без новой сборки.

1. **`colors`** — компоненты поля (клетка, вода, забор…) красятся цветами из `style`. Эффекты тапа, находки и победы в этом режиме — одна простая анимация на слот, которую приложение рисует само: расходящееся кольцо (тап), вспышка с частицами (находка), сияние (победа), в цветах части `fx`. Выбирать её не нужно, это не набор заготовок.
2. **`textures`** — вместо градиента в клетке рисуется картинка из `textures` (`<Image>` или Skia `ImageShader` с повтором для плитки). Цвета `style` остаются для свечения, цифр и всего, чего нет на картинках.
3. **`lottie`** — предмет проигрывается файлом из `animation`. Lottie бывает у любого типа, кроме набора. Если есть `layer_colors`, передай их в `colorFilters`: слой с этим именем перекрашивается, остальные остаются как в файле. Файл уже проверен сервером: без выражений (JavaScript), без внешних ссылок и шрифтов, картинки внутри — только встроенные PNG/JPEG. Чтобы эффект не грузился в момент тапа, скачивай файлы надетых предметов заранее — при входе и после `PUT /me/equipment`.

**Светлая и тёмная тема.** Выбирай набор по теме приложения: в тёмной — `dark`, если он есть, иначе верхний уровень. `render` и `loop` общие для обеих тем. Внутри `dark` всё как у светлой: части без цветов не приходят (рисуй как базовый предмет слота), у `lottie` без своего файла `dark.animation` совпадает со светлой, а `dark.layer_colors` перекрашивает её под тёмную тему. При смене темы перерисовывай поле, скачанные файлы обеих тем кешируй.

Если текстура не скачалась или способ неизвестен — рисуй цветами из `style`, а если их нет — как базовый предмет слота. Если не скачалась анимация — эффект пропусти.

**Много анимаций сразу.** У игрока в слоте один предмет, поэтому все клетки воды на поле — одна и та же анимация, все заборы — одна и та же. Просчитывай её один раз за кадр и рисуй во всех нужных местах. Удобнее всего через Skia (`@shopify/react-native-skia`, Skottie — тот же Lottie JSON): одна анимация, много отпечатков на одном холсте. Анимации с `loop` идут постоянно, без `loop` — только по событию, потом стоят. На паузе и в фоне всё останавливай. Отдельные эффекты (тап, находка, победа) спокойно играются и через `lottie-react-native`.

```tsx
const pickTheme = (it: Item, dark: boolean) => (dark && it.dark ? { ...it, ...it.dark } : it);
const skin = buildSkin(me.equipped, me.items.map((it) => pickTheme(it, scheme === 'dark')));   // слот → { render, style, textures, animation }

function Cell({ kind, value }: CellProps) {
  const s = skin[kind === 'stream' ? 'stream' : 'board'];
  const tex = s.textures?.[kind === 'open' ? 'open' : kind === 'stream' ? 'water' : 'cell'];
  if (s.render === 'textures' && tex) return <Image source={{ uri: API_URL + tex }} style={styles.cell} />;
  const colors = s.style[kind === 'open' ? 'open' : kind === 'stream' ? 'water' : 'cell'] ?? base.cell;
  const fill = colors.length === 1 ? [colors[0], colors[0]] : colors;   // один цвет — сплошной, больше — градиент
  return <LinearGradient colors={fill} style={styles.cell}>{value != null && <Text style={{ color: (skin.number.style.fill ?? base.number)[0] }}>{value}</Text>}</LinearGradient>;
}

function RevealFx({ at }: { at: Point }) {
  const fx = skin.reveal;
  if (fx.render !== 'lottie') return <SimpleFx slot="reveal" colors={fx.style.fx} at={at} />;   // вспышка в цветах fx
  if (!fx.animation) return null;
  const colorFilters = Object.entries(fx.layer_colors ?? {}).map(([keypath, color]) => ({ keypath, color }));
  return <LottieView source={{ uri: API_URL + fx.animation }} colorFilters={colorFilters} autoPlay loop={false} style={at} />;
}
```

### `POST /shop/items/{key}/buy` 🔒 — купить

`{ "price": 1680, "currency": "gems" }` — цена и валюта, которые видел игрок. Подтверждение для покупок от ◆ 500 показывай сам. Без сети кнопка неактивна: «Нужен интернет».

```json
{ "item": { "key": "night", "owned": true, "...": "" }, "granted": ["night"], "wallet": { "coins": 18420, "gems": 960 } }
```

`granted` — что добавилось (у набора — сам набор и недостающие части). Дальше экран «Покупка прошла» с кнопками «Экипировать» и «Позже».

| Ошибка | Что делать |
|---|---|
| 409 `not_enough_gems` / `not_enough_coins` | лист «Как заработать»; в `data.need` — сколько не хватает |
| 409 `price_changed` | цена изменилась: `data.price` — новая цена объектом `{"gems": 450}` или `{"coins": 4200}`. Обнови витрину и спроси игрока снова |
| 409 `sold_out` | тираж закончился — обнови витрину |
| 409 `already_owned` | уже куплено (например, с другого устройства) — обнови витрину |
| 410 `offer_ended` | «Предложение завершено», убери товар из списка. 10 секунд после конца продажи покупка ещё проходит |
| 404 `item_not_found` | товар сняли — обнови витрину |

Шли `Idempotency-Key`: повтор после обрыва сети вернёт тот же ответ «Покупка прошла» и второй раз не спишет.

### `GET /me/items` 🔒 — мои предметы

```json
{ "items": [{ "key": "base", "default": true, "owned": true, "equipped": true, "...": "" }],
  "equipped": { "board": "night", "fence": "", "stream": "", "bomb": "", "marker": "", "tap": "", "reveal": "", "win": "", "frame": "", "title": "", "...": "" },
  "slots": [
    { "slot": "board", "title": "Поле", "equipped": "night", "items": ["base", "night", "creek"] },
    { "slot": "fence", "title": "Забор", "equipped": "base_fence", "items": ["base_fence"] }
  ] }
```

`slots` — блок «Коллекция» в профиле по макету: слоты по порядку, у каждого — что надето и что есть у игрока. Тап по слоту — лист с его предметами (данные из `items` по ключам), выбор сразу вызывает `PUT /me/equipment`. Внизу листа — «Ещё в витрине»: открой витрину на вкладке, где лежат такие предметы.

`equipped` — что надето в каждом слоте: купленный предмет или базовый. Пустая строка — для слота ещё нет базового предмета. Сюда попадает и то, что уже не продаётся: купленное остаётся навсегда.

Поддержка может выдать предмет в компенсацию или забрать (например, при возврате денег) — поэтому список и `equipped` бери с сервера при каждом входе в игру и после возвращения в приложение, а не храни как вечный. Если надетый предмет пропал, в слоте снова будет базовый.

### `PUT /me/equipment` 🔒 — надеть

`{ "slot": "board", "item": "night" }`. `item: ""` — вернуть базовый предмет. Надеть можно только своё и только в свой слот, иначе 422. Ответ — как у `GET /me/items`.

## 10. Арена: PvP по своим картам

Каждый игрок прячет цели и бомбы на своей карте, потом оба по очереди ищут цели на карте соперника, как в морском бое. Сервер хранит обе карты, считает ходы, таймеры, кубки и награды. Приложение только рисует и отправляет тапы: ни чужих целей, ни чужих бомб до конца матча на устройство не приходит.

Форматы лиг, дивизионы, таймеры, бот и награды — из админки. В приложении ничего не хардкодь: размеры поля, лимиты элементов, время хода и пороги кубков бери из ответов.

### Как устроен матч

1. **Поиск** — `POST /arena/queue`. Через `map_offer_at` показать «Играть против карты», в `bot_at` сервер сам начнёт матч с тренировочным соперником.
2. **Подготовка** — до `deadline` игрок рисует карту, берёт сохранённую или случайную (`PUT …/map`) и жмёт «Готов» (`POST …/ready`). Соперник видит только отметку «готов». Не успел — уйдёт активная карта, а если её нет или она не подходит под формат — случайная. `map_seen_by_rival: true` — соперник уже видел выбранную карту целиком в прошлом матче: предложи взять другую.
3. **VS и жребий** — когда готовы оба: `status: "play"`, `first` — кто ходит первым, `starts_at` — конец экрана VS. До него тапы отклоняются (`match_starting`).
4. **Ходы** — по очереди, `move_seconds` на ход, таймер — до `deadline`. Тап по бомбе — пропуск следующего хода (соперник ходит дважды). Не успел — ход пропущен, после `max_timeouts` пропусков — поражение. Тап, пришедший после `deadline`, сервер не примет: засчитает пропуск и ответит 409 `stale_state`. Всего в матче не больше `config.arena.maxTurns` ходов (из `/bootstrap`): дошли до предела — побеждает нашедший больше целей, поровну — ничья (`reason: "max_turns"`).
5. **Финал** — кто первым нашёл все цели, тот побеждает. Если первым нашёл тот, кто ходил первым, у соперника есть финальный ход (`final: true`): найдёт последние цели — ничья по правилу равных ходов.
6. **Итог** — обе карты целиком с тапами обоих, кубки, монеты, изумруды, опыт (`xp`), новый дивизион.

Сдаться можно и на подготовке, и в игре: `surrender_loss` — сколько кубков спишется, покажи это в «Сдаться?».

### События по WebSocket

`GET /arena/ws` 🔒 — подключение с тем же `Authorization: Bearer …`, что у запросов. В React Native: `new WebSocket(url, null, { headers: { Authorization: 'Bearer ' + token } })`. Адрес — `wss://…/api/v1/arena/ws`.

Сервер присылает JSON:

```json
{ "type": "match", "time": "2026-11-02T12:00:03Z", "match": { "...": "MatchView целиком" } }
```

| `type` | Когда |
|---|---|
| `hello` | сразу после подключения |
| `match` | любое изменение матча: соперник найден, выбрал карту, готов, сходил, пропустил ход, матч закончился. Всегда состояние целиком |
| `queue` | статус поиска (после подключения, если матча нет) |

Сравнивай `match.seq`: пришло меньше или столько же, сколько уже есть, — пропусти. Сервер закроет соединение с кодом `4001`, когда истечёт токен или сессия завершится (выход, смена пароля): обнови токен и подключись снова. Сообщения от приложения сервер не принимает (соединение закроется): все действия — обычными запросами. Пинги сервер шлёт сам. Обрыв — переподключись и возьми `GET /arena/matches/current`. Токен истёк — обнови его и подключись заново. Не больше трёх подключений на игрока.

### Мои карты и редактор

Карта — тот же формат, что у уровня: `rows`, `cols`, `terrain` (`.` обычная, `s` ручей, `b` мост, `h` ×2, `r` скала), `fences` (пары соседних клеток), `targets`, `bombs`. Буев и маяков на арене нет. Режим, лимит ходов, туман и порядок целей сервер ставит сам: на арене всегда числовой пеленг без лимита.

| Запрос | Что делает |
|---|---|
| `GET /arena/maps` | до трёх карт и формат лиги. `valid` проверяется под формат текущей лиги: перешёл в лигу с другим размером — карта стала черновиком |
| `POST /arena/maps` | `{ "name": "Карта 1", "level": {…} }`. Невалидная сохраняется черновиком (`valid: false`, причины в `problems`). Первая валидная становится активной. Четвёртая — 409 `maps_limit` |
| `PUT /arena/maps/{id}` | изменить. Активная стала невалидной — активной карты нет, пока не выберешь другую |
| `DELETE /arena/maps/{id}` | удалить |
| `POST /arena/maps/{id}/activate` | «Сменить»: только валидную, иначе 422 `map_invalid` с причинами в `data` |
| `POST /arena/maps/random` | кнопка RANDOM: валидная случайная карта формата, не сохраняется |
| `POST /arena/maps/check` | «Проверить»: `{ "level": {…} }` → `valid`, `problems`, `bot.moves` и `bot.taps` по порядку для анимации бота |

Живую проверку при рисовании (счётчики «поставлено / лимит», отрезанные клетки) делай на клиенте по `format`, сервер проверит при сохранении. `problems[].cells` — клетки для красной штриховки.

### Матч: `GET /arena/matches/{id}` 🔒, `GET /arena/matches/current` 🔒

```json
{
  "id": "…", "kind": "duel", "status": "play", "seq": 12, "server_time": "…",
  "format": { "rows": 7, "cols": 7, "targets": 2, "move_seconds": 7, "league": "gold", "...": "" },
  "me":    { "id": "…", "name": "test", "trophies": 2640, "league": { "league": "gold", "division": "II", "...": "" },
             "look": { "avatar": {…}, "frame": {…}, "title": {…} }, "skins": { "board": {…}, "fence": {…}, "bomb": {…} },
             "ready": true, "found": 1, "moves": 6, "skips": 0, "timeouts": 1 },
  "rival": { "id": "…", "name": "test1", "bot": false, "...": "то же" },
  "turn": "me", "first": "rival", "final": false,
  "deadline": "2026-11-02T12:00:10Z", "starts_at": "2026-11-02T11:59:40Z",
  "my_map":    { "rows": 7, "cols": 7, "terrain": [...], "fences": [...], "targets": 2, "bombs": 3,
                 "revealed": [{ "row": 2, "col": 4, "kind": "number", "value": 3, "tone": "warm", "epoch": 0 }],
                 "taps": [[2, 4]], "secrets": { "targets": [[1, 1], [5, 4]], "bombs": [[3, 3]], "buoys": [] } },
  "rival_map": { "rows": 7, "...": "без secrets до конца матча", "revealed": [...], "taps": [...] },
  "last": { "by": "rival", "cell": [2, 4], "kind": "number", "at": "…" },
  "surrender_loss": 30
}
```

| Поле | Что с ним делать |
|---|---|
| `status` | `prepare` — экран подготовки, `play` — VS и игра, `done` — итог |
| `turn` | `me` — поле яркое, мой таймер; `rival` — поле затемнено, его таймер на кольце. В матче «против карты» нет |
| `deadline` | конец подготовки или текущего хода. Таймер считай от `server_time` |
| `starts_at` | до этого момента — экран VS («Жребий… Первым ходит: …» по `first`) |
| `final` | баннер «Финальный ход!»: соперник нашёл все цели, у ходящего последний шанс на ничью |
| `my_map` | мини-карта сверху: своя карта целиком (`secrets`) и тапы соперника по ней (`revealed`, `taps`). Вспышка, если в `revealed` новая `target` |
| `rival_map` | поле в центре: клетки соперника, которые ты открыл. Рельеф и заборы видны сразу, цели и бомбы — только после матча (`secrets`) |
| `last` | тост: «Соперник на бомбе — ходи ещё» (`kind: "bomb"`, `by: "rival"`), «Время вышло — ход пропущен (`timeouts`/`max_timeouts`)» (`kind: "timeout"`) |
| `me.skips`, `rival.skips` | сколько ходов пропустит из-за бомб |
| `rival.bot` | метка «Тренировочный соперник», кубки ×`bot_factor`% |
| `map_seen_by_rival` | подготовка: соперник уже видел эту карту — подскажи выбрать другую |
| `skins` | что надето у игрока на момент начала матча, в формате витрины. **Карту рисуй скинами её хозяина**: `my_map` — своими, `rival_map` — скинами соперника. Эффекты тапа и находки (`tap`, `reveal`, `win`) — того, кто ходит |
| `look` | аватар, рамка и титул в шапке и на экране VS |

На подготовке `rival_map` нет, `my_map` — выбранная карта (после `random` — сгенерированная сервером).

### Действия в матче

| Запрос | Тело | Что делает |
|---|---|---|
| `PUT /arena/matches/{id}/map` | `{ "source": "draw", "level": {…} }`, `{ "source": "saved", "map_id": "…" }` или `{ "source": "random" }` | выбрать карту до «Готов». Можно менять сколько угодно раз. 422 `map_invalid` — карта не подходит под формат матча |
| `POST /arena/matches/{id}/ready` | — | «Готов». Карта не выбрана — активная или случайная |
| `POST /arena/matches/{id}/tap` | `{ "row": 3, "col": 4, "seq": 12 }` | ход. `seq` — из последнего состояния. 409 `stale_state` — состояние ушло вперёд: возьми матч заново |
| `POST /arena/matches/{id}/surrender` | — | сдаться |

Ответ любого действия — `MatchView` целиком. Кнопку тапа блокируй до ответа, чтобы не ушёл двойной ход.

### Итог матча

```json
"result": { "outcome": "win", "reason": "targets", "trophies": 32, "trophy_now": 2672,
            "league": { "league": "gold", "division": "II", "min": 2400 }, "next": { "division": "I", "min": 2800, "...": "" },
            "coins": 40, "gems": 3, "xp": 10, "rp": 10,
            "promotion": { "league": "gold", "title": "Gold", "division": "I", "min": 2800, "coins": 300, "gems": 20 } }
```

| `reason` | Подпись |
|---|---|
| `targets` | все цели найдены за `me.moves` ходов |
| `final` | соперник не добрал цели в финальный ход |
| `equal` | оба нашли все цели — правило равных ходов (ничья) |
| `timeouts` | слишком много пропусков по времени |
| `surrender` | сдался |
| `norm` | «против карты»: «Ты: N ходов · Норма: `norm`» |
| `abandoned` | «против карты»: время на партию вышло |
| `max_turns` | ходы кончились: больше целей у победителя, поровну — ничья |

`rp` — очки сезонного трека за матч («+10 RP»). `promotion` — отдельный полноэкранный момент «Новый дивизион» с наградой. `coins` и `gems` в `result` уже включают её. После матча обе карты приходят целиком (`secrets`) с тапами обоих: циан — твои, розовый — соперника.

### «Против карты»

`kind: "map"`: соперника нет, `rival` — автор карты, `norm` — сколько ходов тратит бот-решатель. Ходи когда хочешь, без таймера хода (на всю партию — `deadline`). Бомба — +1 ход к итогу: `me.moves` здесь уже с учётом бомб, сравнивай его с `norm`. Меньше нормы — победа, равно — ничья, больше — поражение: как только норма недостижима, матч заканчивается. Кубки и монеты ×`bot_factor`%. Автор карты ничего не теряет: его карте засчитывается защита.

### История и профиль игрока

`GET /arena/history?limit=20&before=…` 🔒 — «История матчей», новые сверху. Следующая страница — `before` из `next_before`.

`GET /arena/players/{id}` 🔒 — профиль игрока из истории или с экрана VS: ник, кубки, лига, место, `look`, `stats` и `head_to_head` — личные встречи с тобой (`wins` — твои победы над ним, последние матчи в `last`). Свой профиль — без `head_to_head`.

### Награды и кубки (настраиваются в админке)

- Кубки — по силе соперника: победа над равным — K/2 (по умолчанию 20), над сильным — больше, над слабым — меньше. Ниже 0 и ниже `floor` не падают.
- За бота и «против карты» — `bot_factor`% кубков и монет. Изумруды — только за победы над живыми игроками, первые несколько за сутки.
- Сдавшийся монет не получает. Победитель того, кто сдался раньше нескольких ходов, изумрудов не получает.
- Защита от договорных матчей: одну пару подряд не сводим, а после нескольких дуэлей пары за сутки кубки и награды за их матчи не начисляются.
- «Против карты» не предлагает карты, которые игрок уже видел целиком.
- Новый дивизион впервые за сезон — награда дивизиона (`promotion`).
- RP за матч: победа 10, ничья 4, поражение 3. Сдавшийся и матчи без наград (договорные) RP не дают.

### Сезон: `GET /arena/season` 🔒

```json
{
  "number": 8, "starts_at": "2026-10-31T09:00:00Z", "ends_at": "2026-11-28T09:00:00Z",
  "rp": 340, "peak": 2672, "ready": 1,
  "track": [
    { "id": 1, "rp": 0, "coins": 200, "gems": 0, "state": "claimed" },
    { "id": 2, "rp": 100, "coins": 0, "gems": 10, "state": "ready" },
    { "id": 5, "rp": 200, "coins": 0, "gems": 0, "item": { "key": "frame_s08", "kind": "frame", "title": "Рамка S08", "image": "/shop/images/…png" }, "state": "locked" }
  ],
  "result": {
    "number": 7, "peak": 3120, "league": { "league": "gold", "title": "Gold", "division": "I", "min": 2800 },
    "rank": 312, "wins": 64, "trophies_before": 3120, "trophies_after": 2560,
    "coins": 1500, "gems": 60, "item": { "key": "frame_s07", "kind": "frame", "title": "Рамка S07" }

```

| Поле | Что с ним делать |
|---|---|
| `ends_at` | «Сезон закончится через 12 дней». Считай от `server_time` из `GET /arena` |
| `rp`, `track` | «Сезонный трек · RP 340». `state`: `locked` — не хватает RP, `ready` — кнопка «Забрать» (подсветка), `claimed` — забрано |
| `ready` | сколько шагов можно забрать: точка на вкладке «Арена» |
| `result` | итог прошлого сезона: модалка «Сезон 07 завершён» при первом входе — пиковая лига, место, награды, «Мягкий сброс кубков 3 120 → 2 560». Кнопка «Забрать» → `POST /arena/season/result/claim`. Нет поля — модалку не показывать |

- `POST /arena/season/track/{id}/claim` 🔒 — забрать шаг. Ответ: `coins`, `gems`, `item`, новый `wallet` и обновлённый `season`. Ошибки: `409 step_locked`, `409 step_claimed`, `404 step_not_found`.
- `POST /arena/season/result/claim` 🔒 — забрать награды итога. Ответ тот же. Нет итога — `404 no_season_result`. Если игрок пропустил несколько сезонов, после первого «Забрать» в `season.result` придёт следующий.
- Предмет из награды сразу попадает в «Мои предметы» (`GET /me/items`); надеть — как обычно.
- Шли `Idempotency-Key` в обоих запросах.

Сезон длится 28 дней и сменяется сам: итоги считаются по пиковой лиге сезона, кубки выше 2 000 становятся 2 000 + половина остатка, RP обнуляются, `floor` пересчитывается от новых кубков, награды дивизионов выше можно взять снова. Длину сезона, порог сброса, RP за матчи, трек и награды лиг меняют в админке.

### Лидерборды: `GET /arena/leaderboard?period=week&scope=all&limit=100` 🔒

```json
{
  "period": "week", "scope": "all", "ends_at": "2026-11-09T21:00:00Z",
  "items": [
    { "rank": 1, "id": "…", "name": "test", "country": "RU", "value": 184, "league": "gold" },
    { "rank": 2, "id": "…", "name": "test1", "value": 152, "league": "silver" }

  "me": { "rank": 134, "id": "…", "name": "test2", "value": 12, "league": "bronze" }
```

| Параметр | Значения |
|---|---|
| `period` | `week` — прирост кубков за неделю (с понедельника 00:00 по Москве; `value` бывает отрицательным), `season` — кубки в текущем сезоне |
| `scope` | `all` — все, `country` — страна из профиля. Страна не указана — пустой `items` и нет `country`: покажи «Укажи страну» |
| `limit` | 1–100, по умолчанию 100. Для блока «Лидеры» на главной арены — `limit=3` |

- В списке только те, кто играл в этот период; удалённые аккаунты и забаненные на арене не попадают.
- `me` — своя строка, прилипает к низу. Нет — игрок ещё не играл в этом периоде.
- `ends_at` — таймер вкладки: конец недели или сезона.
- Медали — `rank` 1–3. Букву аватара бери из `name`, профиль по тапу — `GET /arena/players/{id}`.
- Вкладки «Дейли» и «Друзья» появятся вместе с пеленгом дня и друзьями.

## 12. Готовый клиент на axios

```ts
// api.ts
import axios, { AxiosError, InternalAxiosRequestConfig } from 'axios';
import * as SecureStore from 'expo-secure-store';
import * as Application from 'expo-application';

const API_URL = process.env.EXPO_PUBLIC_API_URL!;
const VERSION = Application.nativeApplicationVersion ?? '0.0.0';

type Tokens = { access_token: string; refresh_token: string };

export const tokens = {
  async get(): Promise<Tokens | null> {
    const raw = await SecureStore.getItemAsync('tokens');
    return raw ? JSON.parse(raw) : null;
  },
  set: (t: Tokens) => SecureStore.setItemAsync('tokens', JSON.stringify({ access_token: t.access_token, refresh_token: t.refresh_token })),
  clear: () => SecureStore.deleteItemAsync('tokens'),
};

export const api = axios.create({ baseURL: `${API_URL}/api/v1`, timeout: 15000 });

api.interceptors.request.use(async (c) => {
  c.headers['X-App-Version'] = VERSION;
  c.headers['Accept-Language'] = i18n.language === 'en' ? 'en' : 'ru';
  // Ключ создаёт вызывающий код на действие игрока и передаёт тот же при повторе: api.post(url, body, { headers: { 'Idempotency-Key': key } }).
  const t = await tokens.get();
  if (t && !c.headers.Authorization) c.headers.Authorization = `Bearer ${t.access_token}`;
  return c;
});

// Один refresh на всех: параллельные запросы ждут один и тот же промис.
let refreshing: Promise<string | null> | null = null;

function refreshAccess(): Promise<string | null> {
  if (!refreshing) {
    refreshing = (async () => {
      const t = await tokens.get();
      if (!t) return null;
      try {
        const res = await axios.post(`${API_URL}/api/v1/auth/refresh`,
          { refresh_token: t.refresh_token },
          { headers: { 'X-App-Version': VERSION } });
        await tokens.set(res.data.data);
        return res.data.data.access_token as string;
      } catch (e) {
        // Сеть упала — токены оставляем. Сервер отказал — выходим.
        if ((e as AxiosError).response) {
          await tokens.clear();
          handlers.signedOut();
        }
        return null;
      } finally {
        refreshing = null;
      }
    })();
  }
  return refreshing;
}

api.interceptors.response.use(undefined, async (error: AxiosError<any>) => {
  const res = error.response;
  const cfg = error.config as InternalAxiosRequestConfig & { _retry?: boolean };
  const code = res?.data?.code;

  if (res?.status === 503 && code === 'maintenance') handlers.maintenance(res.data.message);
  if (res?.status === 426) handlers.update(res.data.data);

  if (res?.status === 401 && code === 'invalid_token' && cfg && !cfg._retry) {
    cfg._retry = true;
    const access = await refreshAccess();
    if (access) {
      cfg.headers.Authorization = `Bearer ${access}`;
      return api(cfg);
    }
  }
  if (res?.status === 401 && (code === 'session_revoked' || code === 'unauthenticated')) {
    await tokens.clear();
    handlers.signedOut();
  }
  return Promise.reject(error);
});

// Подключи к навигации и стору приложения.
export const handlers = {
  signedOut: () => {},
  maintenance: (_message: string) => {},
  update: (_data: unknown) => {},
};

// Ошибка для формы: code, текст и ошибки по полям.
export function apiError(e: unknown) {
  const d = (e as AxiosError<any>).response?.data;
  return {
    code: (d?.code ?? 'network_error') as string,
    message: (d?.message ?? 'Нет соединения с сервером.') as string,
    fields: (d?.errors ?? {}) as Record<string, string>,
  };
}
```

Пример — вход:

```ts
try {
  const res = await api.post('/auth/login', { email, password, device: await getDevice() });
  await tokens.set(res.data.data);
} catch (e) {
  const err = apiError(e);
  if (err.code === 'email_not_verified') { /* экран кода */ }
  setFieldErrors(err.fields);       // под полями
  setFormError(err.message);        // общий текст
}
```

## 13. Безопасность в приложении

- В приложении **нет секретов**: всё, что лежит в сборке, можно достать. Ключи только на сервере.
- Токены и `device_id` — только в `expo-secure-store`. Не AsyncStorage, не Redux persist.
- Не логировать токены, пароли и коды: ни в `console.log` в релизе, ни в Sentry, ни в аналитику.
- Прод только по HTTPS. Разрешения на `http://` (cleartext на Android, исключения ATS на iOS) — только в dev-сборке.
- Не писать игроку «такого аккаунта нет»: сервер нарочно отвечает одинаково, чтобы нельзя было узнать, кто зарегистрирован.
- Кнопки отправки блокировать на время запроса, чтобы не уходили двойные запросы.
- При выходе удалять токены локально, даже если запрос не прошёл.
